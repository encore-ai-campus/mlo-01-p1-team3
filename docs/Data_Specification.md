# Data Specification

## 1. 문서 목적

본 문서는 중고 자동차 영업·고객지원 데이터 통합 솔루션의 **원본 ･ 전처리 ･ 정재 데이터 적재 및 관계성**을 정의한다.

## 2. SQL 테이블 정의

### sales_support_db

본 통합 솔루션의 정형 데이터를 저장 및 관리하는 DB로 해당 테이블 내에 차량 등록 현황 보고, 중고차 데이터를 적재한다.
모든 적재는 ETL을 기반으로 하고 여기서 정의하는 전처리는 가져온 데이터를 DB의 형식에 맞춰 수정하는 것을 의미한다.
해당 전처리 과정에서 내부 데이터의 변조 또는 수정이 이루어지면 안되며, 결측치를 0으로 채우는 것 만을 허용한다.

A. sales_support_db는 실제 솔루션에 사용되는 정형 데이터의 저장 및 관리를 목적으로 한다. 전처리 및 정제된 데이터 일체를 의미한다.
    - a. 중고차 크롤링 데이터: 테이블 4개 예상. 원본 데이터를 크롤링하여 전처리 후 적재하여야 한다. 해당 테이블의 데이터는 없는 데이터는 insert, 존재하고 상태가 변화한 데이터는 update, 존재하고 변화되지 않은 데이터는 그대로 유지되어야 한다.
    - b. 자동차등록현황보고는 원본 API 응답을 DB에서 정의되는 형식에 맞춰 저장되어야 한다. 해당 테이블의 데이터는 API 일 호출 3000 건을 기준으로 최신 데이터를 확인하고 만약 적재된 데이터와 최신 데이터 일자의 차이가 있는 경우 그 사이의 데이터를 요청하는 것이 우선되어야 하며, 이후 이전 데이터를 채우는 것을 진행하여야 한다.
B. application_logs는 해당 솔루션의 운영상 발생하는 에플리케이션 단의 모든 로그를 저장하는 것을 목적으로 한다. 이는 운영 안정성을 검증하고 문제 발생 시 이슈 발생 위치와 이슈 재현성을 목적으로 수집 및 관리한다.
    - 해당 db는 각 레이어 또는 로직 단위의 로그를 적재하여야하며 이를 통해 이슈가 발생하였을 때 서버 단위가 아닌 실제 기능단위 경계로 이슈를 명확히 하여야 한다.
    - 각 로직 단위 로그는 각 테이블별로 저장 및 관리된다.

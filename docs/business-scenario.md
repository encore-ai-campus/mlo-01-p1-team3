### 예시 1. 자동차 보험사 고객 분석 지원 솔루션

가상의 고객사는 전국 단위 자동차 보험상품을 판매하는 보험사야.

현재는 지역별 차량 등록 현황과 고객 FAQ가 서로 다른 시스템에 흩어져 있어서, 지역별 보험 수요 분석과 고객 문의 대응 자료를 한 번에 확인하기 어렵다는 문제를 가지고 있어.

우리 솔루션 업체는:

```text
자동차 등록 공공데이터
→ 지역 / 기준월 / 차종별 정제
→ MySQL 적재
→ 지역별 차량 분포 분석

보험사 FAQ
→ 회사 / 카테고리 / 질문 / 답변 정제
→ MongoDB 적재
→ 고객문의 유형별 조회

Pipeline Scheduler
→ 주기적 갱신

Logging / Evidence
→ 수집·정제·적재 성공 여부 추적
```

이 시나리오의 고객 요구는 예를 들면:

> “서울 노원구의 승용차 등록대수를 확인하고, 동시에 해당 지역 고객에게 자주 발생하는 자동차보험 FAQ를 조회하고 싶다.”

이 설정은 **자동차 데이터와 FAQ가 같은 ‘보험 업무’ 안에서 자연스럽게 연결된다는 장점**이 있어.

### 예시 2. 자동차 제조사 영업·고객지원 데이터 통합 솔루션

가상의 고객사는 전국 판매망을 가진 자동차 제조사.

문제는 지역별 차량 등록 현황은 외부 공공데이터에서 확인하고, 고객 FAQ는 자사 웹사이트에서 따로 관리하기 때문에 **영업팀과 고객지원팀이 각자 데이터를 보고 있다**는 거야.

우리 팀은 솔루션 업체로서:

```text
[시장 데이터]
자동차 등록 데이터
→ 지역별 시장 규모 파악
→ MySQL

[고객지원 데이터]
FAQ
→ 카테고리별 고객 문의 분석
→ MongoDB

[통합 Pipeline]
수집 → 정제 → 검증 → 저장 → 조회
```

예를 들면 영업 담당자가:

> “경기도에서 SUV 등록 비중이 높은 지역을 확인하고 싶다.”

고객지원 담당자는:

> “차량 구매/정비/보증 카테고리 FAQ를 빠르게 조회하고 싶다.”

운영 담당자는:

> “매일 데이터 갱신이 정상 수행되었는지 확인하고 싶다.”

이렇게 이해관계자도 깔끔하게 나뉘어.

### 예시 3. 자동차 렌탈·리스 기업 시장 분석 솔루션

이것도 꽤 자연스러워.

가상의 렌터카/리스 회사가 전국 사업 확장을 검토하고 있다고 치자.

문제:

```text
지역별 자동차 시장 규모 확인 → 공공데이터 따로
상품/계약 FAQ → 홈페이지 따로
실행 이력 → 수동
```

우리 솔루션 업체가:

```text
자동차 등록 현황
→ 지역별 차량 보유 규모
→ 차종별 등록 현황
→ MySQL

렌탈/리스 FAQ
→ 계약
→ 반납
→ 사고
→ 보험
→ MongoDB
```

로 구성해주는 거지.

가상 고객 요구도 현실적이야.

> “어느 지역에 특정 차종이 많이 등록되어 있는지 보고 신규 영업 지역을 검토하고 싶다.”

그리고 고객지원 쪽에서는:

> “사고 처리나 계약 해지와 관련된 FAQ를 카테고리 기준으로 바로 조회하고 싶다.”

### 예시 4. 자동차 관련 공공기관 데이터 통합 조회 솔루션

민간기업 말고 공공기관을 고객으로 잡는 방법도 있어.

가상의 기관이 전국 자동차 등록 현황을 분석하면서, 동시에 여러 유관기관이나 기업의 FAQ 정보를 관리한다고 설정하는 거야.

문제는:

```text
자동차 등록 통계
→ CSV/API

FAQ
→ 개별 홈페이지

업무 담당자가 각각 수동 확인
```

우리 회사가 통합 파이프라인 구축.

이 경우 BRD를 작성하기는 가장 쉬운데, **FAQ와 자동차 데이터 사이의 업무 연관성이 조금 약해질 수 있음**.

### 예시 5. 모빌리티 데이터 컨설팅 플랫폼

아예 우리 고객을 **“자동차·모빌리티 데이터를 활용하는 기업”**으로 넓게 잡는 방법도 있어.

가상의 고객사:

> `MobiInsight`

사업 내용:
자동차 제조사, 렌터카, 보험사 등에 시장 데이터를 제공하는 B2B 데이터 기업.

우리 팀은 이 회사의 데이터 플랫폼 구축을 맡은 솔루션 업체.

```text
외부 자동차 등록 데이터
        ↓
시장분석 데이터

기업 FAQ 데이터
        ↓
고객지원 지식 데이터

        ↓

MobiInsight Data Platform
```

이렇게 하면 두 데이터가 완전히 같은 비즈니스에 속하지 않아도:

> “서로 다른 유형의 외부 데이터를 안정적으로 수집하고 저장하는 데이터 플랫폼 구축”

이라는 **데이터 엔지니어링 프로젝트 자체**가 핵심이 돼.

---

내가 보기엔 이번 과제에는 **1번 보험사**나 **2번 자동차 제조사**가 제일 좋아.

특히 보험사는 꽤 자연스러워.

```text
자동차 등록 데이터
→ 시장 / 지역 분석

FAQ
→ 보험상품 / 가입 / 사고 / 보상 안내
```

둘이 업무적으로 연결되니까 발표할 때도 억지가 적어.

예를 들어 솔루션 업체 소개까지 붙이면:

> **고객사:** 가상의 전국 자동차보험사 `SafeDrive Insurance`
> **문제:** 지역별 자동차 등록현황과 고객 FAQ가 서로 다른 경로로 관리되어 분석·운영·검증이 수작업에 의존
> **우리 회사:** 데이터 플랫폼 구축 전문 솔루션 업체
> **제안:** 자동차 등록 공공데이터와 고객 FAQ를 각각 MySQL과 MongoDB에 적재하는 자동화 데이터 파이프라인 구축
> **기대효과:** 시장 분석 데이터와 고객지원 데이터를 안정적으로 갱신하고, 실행 이력과 품질 결과를 추적 가능하게 함
